# AGENTS

## Project intent

This repository is a forked working tree of `autrainer` used for TIMIT sentence-type
classification under synthetic and cross-domain noise. The important local additions are:

- spectrogram-domain noise augmentations in `autrainer/augmentations/spectrogram_augmentations.py`
- custom trainer behavior in `autrainer/training/training.py`
- experiment configs in `conf/`
- SLURM orchestration scripts in `scripts/`

The generic `README.rst` is upstream `autrainer` documentation. The project-specific notes
originally lived in `CLAUDE.md`.

## Canonical config model

`autrainer` resolves configs from two places:

- bundled defaults in `autrainer-configurations/`
- local overrides and experiment YAMLs in `conf/`

The search path is wired in `autrainer/core/wrappers/main.py`. It always snapshots the local
`conf/` directory first and then appends `autrainer-configurations/`. In practice, run commands
from repo root and use:

```bash
autrainer train -cn <config>.yaml
autrainer fetch -cn <config>.yaml
autrainer preprocess -cn <config>.yaml
```

Do not assume `autrainer-configurations/config.yaml` is the active experiment file. It is the
upstream-style base example. Current experiment entrypoints live in `conf/` and are usually
generated by scripts.

## What matters in this repo

### Base defaults

- `conf/_autrainer_.yaml`: local training defaults used by the experiment YAMLs
- `autrainer-configurations/_autrainer_.yaml`: upstream base reference
- `autrainer-configurations/dataset/TIMIT-sentencetype-16k.yaml`: main dataset used in the
  current sweeps
- `autrainer-configurations/model/Cnn10-32k-T.yaml`: main model used in the current sweeps
- `autrainer-configurations/preprocessing/log_mel_16k.yaml`: preprocessing producing the
  log-mel features used by the augmentations

### Current noise implementations

- `SNR_noise`: synthetic Gaussian-like spectrogram noise with target SNR
- `CrossDomainNoise`: real noise loaded from AudioSet-derived waveform collections and converted
  to log-mel before mixing

Both implementations now mix in linear power space and only over non-padded frames, then convert
back to dB. This is much closer to the intended SNR behavior than the older debugged version.

Important limitation: both noises are injected after preprocessing, in feature space, not at the
waveform level. Treat these experiments as log-mel robustness experiments, not waveform-level
corruption studies.

## Current experiment entrypoints

Use these scripts as the current canonical sweep drivers:

- `scripts/train_cross_domain_v3_optimized.sh`
  - Gaussian + AudioSet sweep
  - writes results to `results/${RUN_ID}`
  - stores checkpoint symlinks in `trained_models/audioset_${RUN_ID}`
  - trains only the diagonal models once, then runs off-diagonal evaluation with `iterations=0`

- `scripts/train_cross_domain_rhythmic_optimized.sh`
  - Gaussian + Rhythmic sweep
  - writes results to `results_rhythmic/${RUN_ID}`
  - stores checkpoint symlinks in `trained_models/${RUN_ID}`
  - same optimization pattern as above

Older scripts are not the default:

- `scripts/train_cross_domain_v3_legacy.sh`: full-training version, much slower
- `scripts/generate_cross_domain_configs.py`: older 3-SNR generator (`-20, 0, 20`)
- `scripts/generate_rhythmic_configs.py`: one-off helper, not the main 6-SNR sweep path

## Naming conventions

Noise-domain abbreviations:

- `G`: Gaussian
- `A`: AudioSet balanced noise
- `R`: Rhythmic AudioSet subset

Examples:

- `GG_train20_test40`: train with Gaussian 20 dB, test with Gaussian 40 dB
- `AG_train40_test10`: train with AudioSet 40 dB, test with Gaussian 10 dB
- `RR_train30_test30`: train/test rhythmic 30 dB

Generated config prefixes also matter:

- `A_*`: optimized AudioSet sweep configs
- `R_*`: optimized rhythmic sweep configs

Do not hand-edit hundreds of generated YAML files in `conf/`. Change the generator or the SLURM
script and regenerate.

## Results layout

Full training runs live under:

```text
results/<run_id>/<experiment_id>/training/<hydra_run_name>/
results_rhythmic/<run_id>/<experiment_id>/training/<hydra_run_name>/
```

Key artifacts:

- `.hydra/config.yaml`: resolved config for the exact run
- `metrics.csv`: dev/train metrics across epochs
- `_best/best_results.yaml`: best dev checkpoint summary for trained runs
- `_best/model.pt`: best checkpoint
- `_test/test_holistic.yaml`: final test metrics
- `timer.yaml`, `hardware.yaml`, `training.log`: runtime diagnostics

Eval-only runs (`iterations: 0`) still create a full run directory, but:

- `metrics.csv` only contains the header
- `_test/test_holistic.yaml` is the primary artifact
- the model is loaded from `model.model_checkpoint`

The optimized scripts rely on this custom eval-only path in `autrainer/training/training.py`.

## Analysis workflow

Use `scripts/analyze_cross_domain_results.py` to summarize completed sweeps.

Typical commands:

```bash
source .venv/bin/activate
python scripts/analyze_cross_domain_results.py
python scripts/analyze_cross_domain_results.py -i results_rhythmic -o analysis_results_rhythmic
python scripts/analyze_cross_domain_results.py -i results --aggregate
```

The script supports:

- single-run analysis
- multi-run aggregation (`--aggregate`)
- Gaussian / AudioSet / Rhythmic category detection
- heatmaps, baseline-degradation plots, robustness plots, and text reports

## Known code caveats

### Dev augmentation currently follows train augmentation

In `autrainer/training/training.py`, `AugmentationManager` is built with:

- `train_augmentation=self.cfg.train_augmentation`
- `dev_augmentation=self.cfg.train_augmentation`
- `test_augmentation=self.cfg.test_augmentation`

This means dev data is evaluated in the train-noise domain, not the target test-noise domain.

Implications:

- diagonal sweeps are fine because train/test noise match
- eval-only off-diagonal runs are fine because there is no dev loop
- true off-diagonal training or noisy-train/clean-test robustness experiments can select the
  checkpoint against the wrong domain

If a new experiment depends on dev matching the final evaluation domain, revisit this first.

### `pip freeze` warning in logs is non-fatal

`autrainer/core/utils/requirements.py` uses `pip freeze`. On the cluster this often emits:

```text
/bin/sh: line 1: pip: command not found
```

This does not necessarily fail the run. It only affects `requirements.txt` capture.

### Generated config churn is expected

The current branch contains many deleted legacy YAMLs and many newly generated 6-SNR configs.
That is normal for this branch. Avoid "cleaning up" generated files unless the experiment design
has actually changed.

### Sensitive helper script

`scripts/download_rhythmic_hf.py` contains a hard-coded Hugging Face token. Do not reuse that
pattern and do not commit new secrets.

## Recommended workflow for new experiments

1. Decide whether the experiment is:
   - diagonal training + off-diagonal eval-only reuse, or
   - full retraining for every condition
2. Encode the matrix in the generator/SLURM script, not by manually editing `conf/`
3. Smoke-test one config with `iterations=1` in `srun`
4. Launch the real sweep with `sbatch`
5. Verify completion by checking for `_test/test_holistic.yaml`
6. Analyze with `scripts/analyze_cross_domain_results.py`

If the experiment changes domain-matching assumptions, re-check:

- noise math in `spectrogram_augmentations.py`
- dev/test augmentation semantics in `training.py`
- whether `iterations=0` still represents the intended evaluation protocol
